The EcosystemEcosystem · 2026-11-03

One workbench, and the habits that grew around it.一个工作台，
和围着它长出来的习惯。

PI is my fork of PI Desktop, an open-source Electron AI workbench. It is open all day, and everything on this page lives in it or works on it.

PI 是我基于开源项目 PI Desktop（Electron AI 桌面工作台）改出来的个人版本，整天开着。这一页上的东西，要么住在它里面，要么在给它干活。

Why it exists为什么会有它

A question might start in a paper, become a note, then turn into code and an experiment. Coming back later often means reconstructing the context: why this approach, what has already been tried, and where that result came from.

一个问题可能始于论文，接着变成笔记、代码和实验。隔一段时间再回来，最费劲的往往是找回上下文：上次为什么选这个方案，试过哪些办法，那个结果又是从哪里来的。

The Ecosystem starts with those everyday gaps. It isn’t a product. It is a set of habits I built, bit by bit, around one workbench.

Ecosystem 从这些日常的断点出发。它不是一个产品，而是我围着一个工作台，一点点搭出来的一套习惯。

The parts各个部分

All in daily use, except where marked.

除标注的以外，都在每天使用。

PIPI

My fork of PI Desktop (Electron, LGPL-3.0). I run it on Windows all day; the assistant, the jobs, the research runs, the browser and the reading workspace all live inside it.

我基于 PI Desktop（Electron，LGPL-3.0）改的个人版本，在 Windows 上整天开着；助手、定时任务、研究流程、浏览器和阅读区都住在里面。

LyraLyra

The always-on assistant. She acts on my behalf; anything irreversible or outward waits for my yes.

常驻的助手。她替我动手；不可逆或对外的事，要等我点头。

  • Her own window, with several chats that share one Lyra
  • A notebook memory, reminders and to-dos
  • Permanent deletion, spending or messaging anyone: she asks first
  • 独立窗口，可以开多个对话，共用同一个 Lyra
  • 记忆本、提醒和待办
  • 永久删除、花钱、对外发消息：先问我

Scheduled jobs定时任务

Work that runs on a clock, so the day starts with things already gathered.

按时跑的活，一天开始时，东西已经收好了。

  • A daily paper digest
  • A GitHub report and a group-chat digest
  • Memory distillation, and a weekly health check
  • 每日论文摘要
  • GitHub 报告和群聊摘要
  • 记忆整理，以及每周一次的健康检查

Research & the institution研究模式与研究院 being built建设中

Research mode handles focused questions. Bigger ones are meant for the institution, where separate roles run them and review never gets mixed into the research. Most of it is built; it hasn’t finished a real run yet.

聚焦的问题走研究模式；更大的将来交给研究院，由不同角色来跑，评审不和研究混在一起。大部分已经建好，还没有完整跑通一轮真实的研究。

  • A director who plans and runs the work
  • Reviewers who check it independently
  • A council for the final call
  • 主持：规划和推进
  • 评审：独立检查
  • 评审会：最后拍板

PI ChromePI Chrome

The browser the agents use, built so I can see and stop what they do on the web.

代理们用的浏览器，让我能看见、也能拦住它们在网页上做的事。

  • Confirmation cards before outward steps
  • An audit log of every step
  • A read-only mirror in the work panel
  • 对外的步骤先弹确认卡
  • 每一步写进审计日志
  • 工作面板里的只读镜像

Reading workspace阅读区

Papers and notes beside the conversation, so reading doesn’t mean switching apps.

论文和笔记就在对话旁边，读东西不用切换应用。

  • My Zotero library
  • My Obsidian notes
  • PDF highlights and notes saved back to Zotero
  • Zotero 文献库
  • Obsidian 笔记
  • PDF 上的高亮和批注写回 Zotero

Coding agents编码代理

Claude Code and Codex. They write everyday code with me, and most of PI’s own changes go through them too.

Claude Code 和 Codex。日常的代码和它们一起写，PI 自己的改动也大多经过它们。

State & release rules状态与发布的规矩 house rule规矩

The unglamorous part that keeps the rest from breaking.

不起眼，但让其他部分不出乱子的那一层。

  • State files are read and written strictly
  • A new build is built, then checked
  • Only then does it replace the running one
  • 状态文件严格读写
  • 新版本先构建、再检查
  • 确认无误，才替换正在用的那一版

How a day runs一天，大概这样过

Not a schedule, just the usual order of things. Lyra is around all day.

不是精确的日程表，只是平常的顺序。Lyra 全天都在。

  1. Early清晨

    The digests arrive first摘要先到

    The day starts with what the jobs have collected: the paper digest, the GitHub report, and what happened in the group chats. Lyra puts today’s reminders next to them.

    一天从定时任务收集来的东西开始：论文摘要、GitHub 报告，还有群聊里聊了些什么。Lyra 把今天的提醒一起摆出来。

  2. Morning上午

    Reading first先读

    A few papers from the digest, read in the side panel next to the conversation. Highlights and notes go back to Zotero.

    从摘要里挑几篇论文，在对话旁边的侧栏里读；高亮和批注写回 Zotero。

  3. Daytime白天

    Making things动手

    Writing code with Claude Code and Codex, including changes to PI itself. Steps that need the web go through PI Chrome.

    和 Claude Code、Codex 一起写代码，PI 自己的改动也在其中。需要上网的步骤交给 PI Chrome。

  4. When it needs digging需要深挖时

    Research mode研究模式

    Focused questions go through research mode. The bigger ones are meant for the institution, but it isn’t part of the day yet: it hasn’t finished its first real run.

    聚焦的问题走研究模式。更大的问题本该交给研究院，但它还不在日常里——还没有完整跑通第一轮真实的研究。

  5. Evening晚上

    Tie off the threads收线

    Memory distillation gathers what the day left behind, so tomorrow can pick up from there.

    记忆整理把一天留下的线索归拢好，明天从这里接着走。

  6. Weekly每周

    A check-up体检

    A health check runs once a week. New PI builds get the same care: built and checked before they replace the running one.

    每周跑一次健康检查。PI 有新版本时也一样：先构建、检查，确认无误再替换。

Three rules they all keep它们都守的三条

  1. Do what can be done without me. Not everything needs a question.
  2. Ask before the irreversible or outward. Permanent deletion, spending, or messaging someone needs my yes.
  3. Leave a record of every step. Audit logs and receipts, so it can be checked later.
  1. 能自己做的，就自己做。不必事事来问我。
  2. 不可逆或对外的，先问。永久删除、花钱、对外发消息，都要我点头。
  3. 每一步都留记录。审计日志和回执，事后能查。

Public, and not public yet哪些公开，哪些还没有

Public公开的

This site and its source; every merged upstream PR; and PI Desktop itself, which belongs to its own authors.

这个网站和它的源码；每一个合并到上游的 PR；以及 PI Desktop 本身，它属于自己的作者。

Not yet还没有

My PI build, with everything on this page inside it. It is wired to my own machine and accounts, with no installer, docs or support. Memory, digests and job output are personal and stay that way. The drawing above is a diagram, not a screenshot.

我的 PI 构建，以及这一页上的所有部分。它连着我自己的机器和账号，没有安装包、文档或支持。记忆、摘要和任务产出是私人的，不会放上来。上面那张图是示意，不是界面截图。

If a piece becomes something other people can use, it will show up here first.

如果哪一部分变成别人也能用的东西，会先出现在这里。
